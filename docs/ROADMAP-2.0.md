# خارطة الطريق — من 1.5 إلى 2.0

هذه الوثيقة تحوّل متطلبات «GitHubUploader Ultimate» إلى خطة مراحل حقيقية قابلة للتنفيذ، مع توثيق الحالة الفعلية لكل محور.

> الحقيقة = منفذة ومتحقَّق منها في الكود. التوصية = مخططة. افتراض = قرار هندسي موثق.

## المرحلة الحالية — 1.5 (منفذة ✅)

| المحور | الحالة | الملاحظات |
|---|---|---|
| مصادقة Device Flow | ✅ حقيقة | رسمية عبر `github.com/login/device`، polling مع slow_down |
| مصادقة PAT | ✅ حقيقة | تحقق عبر `GET /user` قبل الحفظ |
| تخزين مشفّر | ✅ حقيقة | EncryptedSharedPreferences + AES256_GCM + ترحيل تلقائي |
| تعدد الحسابات | ✅ حقيقة | حفظ/تبديل من الإعدادات |
| حجب لقطات الشاشة للشاشة الحساسة | ✅ حقيقة | FLAG_SECURE على شاشة الدخول فقط |
| كشف الملفات الحساسة (ذكاء محلي) | ✅ حقيقة | أسماء + امتدادات + أنماط محتوى سرية |
| اقتراح رسالة Commit (ذكاء محلي) | ✅ حقيقة | تحليل مسارات الملفات المختارة |
| إعادة المحاولة (rate limit + شبكة) | ✅ حقيقة | backoff متدرج + Retry-After + pacing |
| تقليل الحجم | ✅ حقيقة | R8 + shrinkResources: 5.29MB → 2.1MB |
| RTL عربي كامل | ✅ حقيقة | attachBaseContext يفرض Locale("ar") |

## المرحلة 2 — 1.6 (التوصية: قصيرة المدى)

- **WorkManager للرفع في الخلفية**: نقل محرك الرفع إلى Foreground Service مع إشعار تقدم، يستمر عند إغلاق التطبيق. (تعقيد: متوسط — المخاطرة: إعادة هيكلة `UploadEngine.upload` إلى نطاق مستقل عن MainActivity)
- **رفع متعدد الحسابات في الجلسة نفسها**: اختيار الحساب الهدف لكل عملية رفع.
- **Web OAuth مع PKCE**: intent-filter `githubuploader://oauth` + state + PKCE — يتطلب OAuth App مع redirect URI مسجل (افتراض: خطوة إعداد يدوية من المستخدم).
- **سجل العمليات (UploadLog)**: Room بسيط (مسار، مستودع، نتيجة، وقت) قابل للبحث.

## المرحلة 3 — 1.7 (التوصية: متوسطة المدى)

- **MVVM + Repository + Hilt**: استخراج منطق الأعمال من MainActivity (~1300 سطر) إلى ViewModels ومستودعات.
- **Room/DataStore كاملة** + **Jetpack Navigation Compose** لفصل الشاشات.
- **وضع عدم الاتصال + قائمة انتظار**: تخزين عمليات رفع معلقة ومزامنة تلقائية عند توفر الشبكة.
- **BiometricPrompt** قبل كشف التوكنات (يتطلب تركيب بصمة/قفل جهاز).
- **معاينة الملفات قبل الرفع** + قائمة قابلة للتعديل (استبعاد ملف فردي).

## المرحلة 4 — 2.0 (التوصية: طويلة المدى)

- **Jetpack Compose** بإعادة رسم الواجهات بنظام تصميم موحد (ألوان GitHub: `#238636`).
- **SSL Pinning** لـ api.github.com (ملاحظة: يزيد مخاطرة كسر التطبيق عند تغيّر شهادات GitHub — يوصى بـ `certificate transparency` بدلاً منه).
- **AI محلي فعلي** (ملخصات على الجهاز) — بمكتبة صغيرة خفيفة، والوضع الحالي (قواعد ذكية بلا ML) يغطي 80% من الفائدة بلا تكلفة.
- **CI/CD**: GitHub Actions يبني APK ويشغّل lint على كل PR.
- **النشر**: GitHub Releases بعدها F-Droid (يتطلب شكلاً Free/Open-source رخصة واضحة) ثم Play (يتطلب Data Safety + Developer account).

## مؤشرات النجاح المستهدفة (2.0)

- معدل نجاح الرفع ≥ 99% (قابل للقياس من تمريرات إعادة المحاولة الحالية + سجل UploadLog القادم)
- Crash Rate < 1% — يتطلب إضافة تقرير أعطال ( افتراض: لن نستخدم Firebase؛ سجل محلي + مشاركة سجل من الإعدادات)
- حجم APK < 15MB ✅ (منجز فعلياً: 2.1MB)
- Time-to-First-Upload < 60 ثانية

## المخاطر الأبرز

| الخطر | التخفيف |
|---|---|
| إعادة هيكلة كبيرة تكسر رفع الملفات | خطة مرحلية: كل مرحلة تبقى قابلة للبناء والتشغيل |
| R8 يكسر توافق الإصدارات القديمة للتحديث الداخلي | نفس التوقيع مُحافظ عليه (keystore واحد، نفس applicationId) |
| PKCE/OAuth Web يحتاج إعداد حسابي يدوي | توثيق خطوات الإعداد في README قيد الإعداد |
